混用引起的后果：

next（），nextInt（），nextDouble（）为一套配套使用，nextLine（）单独使用，如果混用，会有严重的后果。

1

Scanner sc = new Scanner(System.in);//①
int i = sc.nextInt();//②
String s = sc.nextLine();//③
System.out.println(i);//④
System.out.println(s);//⑤

当代码运行到第二行，会让我们键盘录入，此时录入123。
但是实际上我们录的是123+回车。
而 nextInt 是遇到空格，回车，制表符都会停止。
所以 nextInt 只能接受123，
回车还在内存中没有被接收，此时就被 nextLine 接收了。
所以，如果混用就会导致nextLine接收不到数据。

方法重载

  • 概念：方法重载指同一个类中定义的多个方法之间的关系，满足下列条件的多个方法相互构成重载
    • 多个方法在同一个类中
    • 多个方法具有相同的方法名
    • 多个方法的参数不相同，类型不同或者数量不同，或者顺序
Note

  • 重载仅对应方法的定义，与方法的调用无关，调用方式参照标准格式

  • 重载仅针对同一个类中方法的名称与参数进行识别，与返回值无关，换句话说不能通过返回值来判定两个方法是否相互构成重载

        Scanner scanner = new Scanner(System.in);

        double weight;

        // 输入重量并验证
        while (true) {
            System.out.print("请输入快递重量(kg): ");
            weight = scanner.nextDouble();
            if (weight <= 0) {
                System.out.println("重量必须大于0，请重新输入！");
            } else {
                break;
            }

        // 计算运费
        double cost = calculateCost(weight);
        System.out.println("快递重量:" + weight);
        System.out.println("运费:" + cost);
    }

    // 计算总费用
    public static double calculateCost(double weight) {
        double baseCost = 10.0; // 首重1kg费用

        if (weight <= 1.0) {// 首重1kg以内
            return baseCost;

        } else if (weight > 1.0 && weight <= 6.0) {// 总重1-6kg（超出1-5kg）
            // 1. 计算超出部分的重量
            double overWeight = weight - 1.0;
            // 2. 计算超出部分的价格
            int fullKg = ceil(overWeight);
            return baseCost + fullKg * 2.0;

        } else {// 总重超过6kg（超出5kg以上）
            // 1. 计算前6kg的价格
            double cost = baseCost + 5 * 2.0;

            // 2. 计算超出6kg的部分（向上取整）
            double overWeight = weight - 1.0;
            int fullKg = ceil(overWeight);

            // 3. 剩余部分按1.5元计算
            if (fullKg > 5) {
                cost += (fullKg - 5) * 1.5;
            }
            return cost;
        }
    }

    // 小数向上取整
    // 1.1 -> 2
    // 1.8 -> 2
    public static int ceil(double weight) {
        // 备注：此时无需考虑负数，因为在main方法中已经判断过，以后本方法可以用Math里面的ceil替代
        // 如果是整数，直接返回
        if(weight % 1 == 0){
            return (int)weight;
        }

        // 如果是小数，则向上取整
        return (int) (weight + 1);
    }
}

    public static double calculateOverCost(int kg) {
        // 无超重
        if (kg <= 0) {
            return 0.0;
        }

        // 超重 1kg ~ 5kg
        if (kg <= 5) {
            return kg * 2.0;
        }

        // 超重5kg（前5kg按2元/kg，剩余部分按1.5元/kg）
        return 5 * 2.0 + (kg - 5) * 1.5;
    }

      package com.itheima.test;

public class Test5 {
    public static void main(String[] args) {
        /*
        给定 n 个非负整数表示每个宽度为 1 的柱子的高度图，计算按此排列的柱子，下雨之后能接多少雨水
        输入：height = [0,1,0,2,1,0,1,3,2,1,2,1]
        输出：6
        解释：下面是由数组 [0,1,0,2,1,0,1,3,2,1,2,1] 表示的高度图，在这种情况下，可以接 6 个单位的雨水（蓝色部分表示雨水）
        */

        // 1. 定义数组
        int[] arr = {0, 1, 0, 2, 1, 0, 1, 3, 2, 1, 2, 1};

        // 2. 从左往右遍历,记录雨水 + 柱子的面积总和
        // 2.1 定义数组记录从左往右看的数据
        int[] leftMax = new int[arr.length];

        // 2.2 定义第三方变量temp，记录当前最高的柱子
        int temp = arr[0];

        // 2.3 遍历数组
        for (int i = 0; i < arr.length; i++) {
            // 判断 temp  数组里面的数据
            if(temp > arr[i]){
                leftMax[i] = temp;
            }else{
                leftMax[i] = arr[i];
                temp = arr[i];
            }
        }

        // 3. 从右往左遍历,记录雨水 + 柱子的面积总和
        int[] rightMax = new int[arr.length];
        temp = arr[arr.length - 1];

        for (int i = arr.length - 1; i >= 0; i--) {
            if(temp > arr[i]){
                rightMax[i] = temp;
            }else{
                rightMax[i] = arr[i];
                temp = arr[i];
            }
        }

        // 4. 取交集
        int[] result = new int[arr.length];

        for (int i = 0; i < rightMax.length; i++) {
            // leftMax[i]: 从左到右数组中的数据
            // rightMax[i]: 从右到左数组中的数据
            if(leftMax[i] < rightMax[i]){
                result[i] = leftMax[i];
            }else{
                result[i] = rightMax[i];
            }
        }

        // 5. 求和
        int sum = 0;
        for (int i = 0; i < result.length; i++) {
            sum = sum + result[i];
        }

        // 6. 去掉柱子的面积
        for (int i = 0; i < arr.length; i++) {
            sum = sum - arr[i];
        }

        System.out.println(sum);
    }
}

      在 Java 语境中属性 ≈ 具有 getter/setter 方法的私有成员变量

  • JavaBean类

    JavaBean 类可以写变量和行为（方法），Javabean 类的方法不加 static

    • JavaBean 规范中的“属性”定义：
      • 一个私有成员变量（如 private String name;）
      • 对应的公共 getter 和 setter 方法（如 getName(), setName(...)）
      • 这样的组合被称为一个 property （属性）

  • 其他

    1. 字段（Field） = 成员变量
      在 Java 官方文档中，“field” 和 “member variable” 基本同义。
    2. public 成员变量算不算“属性”？
      技术上可以算，但不符合封装原则。JavaBean 规范要求属性通过 getter/setter 访问，所以通常“属性”隐含了封装性。
    3. 只读属性？
      如果只有 getter 没有 setter（如 getAge() 但无 setAge()），仍算作一个只读属性。

  • 成员变量是 Java 代码中的实际变量；属性是面向对象设计中表示对象状态的逻辑概念，通常由私有成员变量及其 getter/setter 方法共同构成。

继承中构造方法

子类的初始化过程中，必须先执行父类的初始化动作。子类的构造方法中默认有一个super() ，表示调用父类的构造方法，父类成员变量初始化后，才可以给子类使用。

继承后子类构方法器特点：子类所有构造方法的第一行都会默认先调用父类的无参构造方法。

小结：

  • 子类的每个构造方法中均有默认的super()，调用父类的空参构造。手动调用父类构造会覆盖默认的super()
  • super() 和 this() 都必须是在构造方法的第一行，所以不能同时出现
  • super(..)和this(…)是根据参数去确定调用父类哪个构造方法的
  • super(..)可以调用父类构造方法初始化继承自父类的成员变量的数据
  • this(..)可以调用本类中的其他构造方法

由于静态方法中没有this和super关键字，所以不能在静态方法中使用this和super，否则会报错！

  • 构造方法：不能被子类继承，可以利用 super 关键字调用

  • 成员变量：可以被子类继承，private 私有的也可以，但是私有的无法直接调用（通过get/set）

    • 虚方法可以被继承

    • final 修饰的最终方法不能被继承，可以被调用

      • 编译期：一级一级往上找，遍历整个继承链，确定要调用的方法在A类里面，记录该方法的地址
      • 运行期：直接运行编译时确定的方法，虽然降低了编译的速度，但是运行的速度会得到保证

    • static 修饰的静态方法不能被继承，可以被调用

      • 编译期：一级一级往上找，遍历整个继承链，确定要调用的方法在A里面将对象调用方法直接修改为类名调用方法
      • 运行期：直接运行

    • private 修饰的私有方法不能被继承，不能被调用

    • 方法重写：子类替换虚方法表里面方法的地址值

局部内部类

  • 定义位置

    • 局部内部类是定义在方法、代码块或构造器内部的类，作用域仅限于该方法或代码块内部，类似于方法内的局部变量。

    • 不能使用 private、protected、public 或 static 修饰符，其作用域被限定在声明它的代码块内。

  • 访问限制

    • 外部无法直接使用局部内部类，必须在其所在的方法内部创建对象并使用。

    • 若要访问方法内的局部变量，该变量必须是 final 或 effectively final（即一旦赋值后不再修改），这是为了保证内部类实例与局部变量生命周期的一致性。

  • 成员访问权限

    • 可以直接访问外部类的所有成员（包括私有成员）。

    • 可以访问所在方法内的 final 或 effectively final 局部变量。

      从 JDK 8 开始，只要局部变量在初始化后没有被修改，就可以被访问（即 “effectively final”）。

  • 编译与命名

    编译器生成的类名格式为：外部类名$数字内部类名，例如 Outer$1LocalInner。

创建方式 语法示例 功能说明
new + 空参构造 String s1 = new String(); 创建空白的字符串对象，不包含任何内容
new + 传字符串有参构造 String s2 = new String(“ABC”); 根据传入的字符串内容，创建一个新的字符串对象（开发中极少使用，面试高频）
new + 传字符数组有参构造 char[] chs = {‘a’, ‘b’, ‘c’}; String s3 = new String(char[] chs); 将字符数组中的所有字符拼接，生成新的字符串对象
new + 传字节数组有参构造 byte[] = {97, 98, 99}; String s4 = new String(byte[] bytes); 根据 ASCII 码表，将字节数组中的整数转换为对应字符，拼接成新字符串对象
public String(byte[] bytes, int offset, int length) 根据字节数组的部分内容创建字符串对象，从offset索引开始，长度为length

使用字节数组构造字符串时，字节数组中的整数需符合 ASCII 码表规则（不超过 127），如 97 对应小写a、98 对应小写b，以此类推。

  • 两种创建方式的内存结构差异

    字符串常量池（串池）基础

    • 别名：字符串常量池，作用是存储字符串对象，实现复用以节约内存；
    • 内存位置：JDK7 以前位于方法区，JDK7 及以后被挪到堆内存中，无论位置如何，运行机制保持不变。

    直接赋值的内存机制

    • 执行流程：栈中声明局部变量 → 虚拟机检查串池是否存在该字符串 → 若不存在，在串池中创建该字符串对象并将地址赋值给变量；若存在，直接复用串池中已有对象的地址，赋值给变量。

    • 核心优势：复用机制，避免重复创建对象，节约内存，且代码简洁。

    new + 构造方法的内存机制

    • 核心规则：只要使用new关键字，就会在堆内存中开辟新的内存空间，无复用机制，每new一次就会创建一个新的字符串对象。
    • 执行流程：栈中声明局部变量 → 堆中开辟新空间创建字符串对象 → 将堆中新对象的地址赋值给栈中的变量；多次new会生成多个不同地址的对象，即使内容相同。

字符串的比较

  1. ==

    • 基本数据类型：比较变量存储的实际数值（如int a=10; int b=10; a==b结果为true）。

    • 引用数据类型（如 String）：比较变量存储的内存地址，而非对象的内容。

      • 示例：String s1 = new String("张三"); String s2 = new String("张三"); s1==s2结果为false，因为new会创建两个不同的对象，内存地址不同。
      • 补充：直接赋值的字符串（String s3="张三"; String s4="张三"）会进入字符串常量池，地址相同，s3==s4结果为true；
        而new创建的字符串不会进入常量池，这是==判断结果不同的关键原因。

  2. String类的比较方法（比较内容）

  • (1) equals(Object anObject)

    • 作用：严格比较两个字符串的内容是否完全一致（包括大小写、字符顺序），返回boolean。

    • 用法：字符串1.equals(字符串2)，例："张三".equals("张三")→true，"张三".equals("张叁")→false。

  • (2) equalsIgnoreCase(String anotherString)

    • 作用：忽略大小写比较字符串内容，返回boolean。

    • 用法：字符串1.equalsIgnoreCase(字符串2)，
      例："Abc".equalsIgnoreCase("aBC")→true。

字符串的遍历

  • charAt(int index)

    • 作用：根据指定索引返回字符串中对应的单个字符，返回值类型为char。
    • 用法：字符串.charAt(索引)，例：“你好123”.charAt(3)→‘2’。
    • 异常：索引超出范围时，抛出StringIndexOutOfBoundsException（字符串索引越界异常），与数组越界异常一致。

  • length()

StringBuilder 工具类

  • 拓展知识点（文档未提及但高频考点）

    1. StringBuilder 的扩容机制
      StringBuilder 底层基于字符数组实现，默认初始容量为16 个字符。当添加的内容超过当前容器容量时，会自动扩容：

      • 扩容规则：新容量 = 原容量 * 2 + 2；

      • 示例：初始容量 16，满后扩容为162+2=34，再满扩容为342+2=70，以此类推；

      • 优化：若提前知道拼接字符串的大致长度，使用StringBuilder(int capacity)指定初始容量，避免多次扩容带来的性能损耗。

    2. StringBuilder 的线程安全性
      StringBuilder 是非线程安全的，在多线程环境下进行字符串拼接 / 修改，可能会出现数据错乱的问题。

      • 解决方案：多线程场景下使用StringBuffer（StringBuilder 的线程安全版本），其方法通过synchronized加锁，保证线程安全，但效率略低于 StringBuilder；

    3. JDK 对 String 拼接的优化
      JDK5 及以上版本，对String的+拼接做了编译期优化：若在单个语句中进行简单的+拼接，编译器会自动将其转换为 StringBuilder 的append拼接，避免冗余对象。

      • 优化场景：String s = “A” + “B” + “C”;（编译后等价于 StringBuilder 拼接，效率高）；
      • 不优化场景：循环中的+拼接（编译器无法优化，仍会创建大量冗余对象，必须手动使用 StringBuilder）。

    4. 字符串操作的选型原则
      开发中根据业务场景选择 String、StringBuilder、StringBuffer，核心原则：

      • 字符串固定不变：用 String（如常量、配置项）；
      • 单线程下动态拼接 / 修改：用 StringBuilder（开发中最常用）；
      • 多线程下动态拼接 / 修改：用 StringBuffer（如多线程日志拼接）。

    数组初始化与遍历：动态初始化指定长度的数组（如char[] arr = new char[52]存储所有字母），for 循环遍历实现数据填充 / 提取；

    数组索引规律：利用数组索引的连续性，批量生成有序数据（如a-z/A-Z）。

ArrayList类

  • 集合
    数组是固定长度的容器，添加/删除元素时需手动创建新数组并复制数据，操作繁琐；集合是长度可变的容器，支持自动扩容/缩容，无需关注容器长度，直接操作数据即可。

  • 核心特点

    • 长度可变，底层基于数组实现（自动扩容，默认初始容量10，扩容为原容量1.5倍）；

    • 只能存储引用数据类型，不能直接存储基本数据类型（需通过包装类转换，如int→Integer）；

    • 有序集合，元素存入顺序与取出顺序一致，支持通过索引操作元素；

    • 允许存储重复元素，允许存储null值。

  • 泛型

    • 作用：限定集合中存储的数据类型，编译期就会做类型校验，避免添加错误类型元素，取出时无需强制类型转换，提升代码安全性和可读性；

    • 使用格式：ArrayList<数据类型> 集合名 = new ArrayList<>();（JDK7新特性：菱形语法，右侧泛型可省略，编译器自动推导）。

  • 四大核心操作（增删改查）

    • 集合操作均通过方法实现，核心方法分为四类，索引从0开始，操作索引时超出范围会抛出IndexOutOfBoundsException（索引越界异常），具体方法如下：
操作类型 方法名 功能说明 返回值/注意事项
增 add(E e) 向集合末尾添加元素 boolean：ArrayList中永远返回true（为与其他集合统一设计），返回值可以忽略
增 add(int index, E e) 向指定索引位置添加元素 void；索引范围0~集合长度（等于长度时添加到末尾）
删 remove(Object o) 根据元素内容删除元素 boolean：删除成功返回true，元素不存在返回false
删 remove(int index) 根据索引删除元素 E：返回被删除的元素；索引需存在
改 set(int index, E e) 将指定索引的元素修改为新元素 E：返回被替换的旧元素；索引需存在
查 get(int index) 根据索引获取元素 E：返回指定索引的元素；索引需存在
辅助 size() 获取集合中元素的实际个数（区别于数组的length） int：集合的有效长度

  1. 关键细节

  2. add(E e)的返回值：ArrayList中始终返回true，一定会添加成功
    设计该返回值是为了与Java集合体系中的其他集合（如HashSet，不允许重复元素，重复添加返回false）保持统一；

  3. 集合遍历：通过get(int index)+size()结合for循环实现
    IDEA：list.fori

  4. 基本数据类型存储：需使用包装类（byte→Byte、short→Short、int→Integer、long→Long、float→Float、double→Double、char→Character、boolean→Boolean），JDK5自动装箱/拆箱，可直接写基本数据类型值（如list.add(10)，编译器自动转为Integer.valueOf(10)）。

  5. 集合体系的设计思想
    Java中所有集合都有增删改查的共性方法，这些方法被抽取到顶层接口（如Collection、List）中，ArrayList作为实现类重写这些方法，保证了集合体系的方法统一，调用不同集合的同类方法时无需重新学习，符合面向对象的抽象和多态思想。

import java.util.ArrayList;
import java.util.Objects;

/**
 * ArrayList优化版代码：兼顾可读性、复用性、异常规避，补充实际开发高频用法
 */
public class ArrayListOptimizeDemo {
    public static void main(String[] args) {
        // 1. 演示字符串类型集合的增删改查（核心）
        ArrayList<String> strList = new ArrayList<>();
        operateStringList(strList);

        // 2. 演示基本数据类型存储（自动装箱/拆箱，泛型为包装类）
        System.out.println("\n===== 基本数据类型（int）存储演示 =====");
        ArrayList<Integer> intList = new ArrayList<>();
        intList.add(10); // 自动装箱：int→Integer
        intList.add(20);
        intList.add(30);
        printCollection(intList); // 调用工具方法打印
        // 自动拆箱：Integer→int
        int num = intList.get(0);
        System.out.println("索引0的int值：" + num);
    }

    /**
     * 封装字符串类型ArrayList的增删改查操作，提升复用性
     * @param strList 字符串类型ArrayList
     */
    private static void operateStringList(ArrayList<String> strList) {
        // 判空：实际开发中操作集合前先判空，避免空指针
        if (Objects.isNull(strList)) {
            System.out.println("集合对象为null，无法操作");
            return;
        }

        // 增：添加元素
        addElements(strList);
        System.out.println("====	= 添加元素后 =====");
        printCollection(strList);

        // 删：删除元素（规避索引越界）
        removeElements(strList);
        System.out.println("\n===== 删除元素后 =====");
        printCollection(strList);

        // 改：修改元素（规避索引越界）
        updateElement(strList, 0, "ZZZ");
        System.out.println("\n===== 修改元素后 =====");
        printCollection(strList);

        // 查：获取单个元素+多种遍历方式
        getAndTraverseList(strList);
    }

    /**
     * 增：添加元素（末尾+指定索引）
     */
    private static void addElements(ArrayList<String> list) {
        list.add("AAA");
        list.add("BBB");
        list.add("CCC");
        list.add(0, "QQQ"); // 指定索引添加
        list.add(list.size(), "DDD"); // 末尾添加（等同于add(E e)）
    }

    /**
     * 删：删除元素（根据内容+根据索引，索引合法性判断）
     */
    private static void removeElements(ArrayList<String> list) {
        // 根据元素内容删除
        boolean removeFlag = list.remove("QQQ");
        System.out.println("删除元素QQQ：" + (removeFlag ? "成功" : "失败"));

        // 根据索引删除：先判断索引是否合法，规避IndexOutOfBoundsException
        int delIndex = 0;
        if (isIndexValid(list, delIndex)) {
            String delElement = list.remove(delIndex);
            System.out.println("删除索引" + delIndex + "的元素：" + delElement);
        } else {
            System.out.println("索引" + delIndex + "不合法，无法删除");
        }
    }

    /**
     * 改：修改指定索引元素，索引合法性判断
     * @param list 集合
     * @param index 要修改的索引
     * @param newElement 新元素
     */
    private static void updateElement(ArrayList<String> list, int index, String newElement) {
        if (isIndexValid(list, index)) {
            String oldElement = list.set(index, newElement);
            System.out.println("索引" + index + "修改：旧元素=" + oldElement + "，新元素=" + newElement);
        } else {
            System.out.println("索引" + index + "不合法，无法修改");
        }
    }

    /**
     * 查：获取单个元素+多种遍历方式（基础for→增强for→forEach流式遍历）
     */
    private static void getAndTraverseList(ArrayList<String> list) {
        // 获取单个元素
        int getIndex = 0;
        if (isIndexValid(list, getIndex)) {
            String getElement = list.get(getIndex);
            System.out.println("\n索引" + getIndex + "的元素：" + getElement);
        }

        // 遍历方式1：基础for循环（支持索引操作，可修改元素）
        System.out.println("\n遍历方式1：基础for循环");
        for (int i = 0; i < list.size(); i++) {
            System.out.println("索引" + i + "：" + list.get(i));
        }

        // 遍历方式2：增强for循环（简化写法，无索引，仅遍历）
        System.out.println("\n遍历方式2：增强for循环");
        for (String s : list) {
            System.out.print(s + " ");
        }
        System.out.println();

        // 遍历方式3：forEach流式遍历（JDK8+，简洁高效，推荐）
        System.out.println("\n遍历方式3：forEach流式遍历");
        list.forEach(s -> System.out.print(s + " "));
        System.out.println();
    }

    /**
     * 工具方法：判断索引是否合法
     * 合法范围：0 <= index < 集合.size()
     */
    private static boolean isIndexValid(ArrayList<?> list, int index) {
        return index >= 0 && index < list.size();
    }

    /**
     * 工具方法：打印集合（通用泛型，支持任意类型集合）
     */
    private static <T> void printCollection(ArrayList<T> list) {
        System.out.println("集合内容：" + list + "，实际元素个数：" + list.size());
    }
}

四、补充拓展知识点（实际开发高频）

  1. ArrayList的扩容机制
  • 初始容量：默认10（空参构造new ArrayList<>()，JDK8+懒加载，首次添加元素时才初始化容量为10）；
  • 扩容触发：当添加元素后实际元素个数 > 数组容量时，触发扩容；
  • 扩容规则：新容量 = 原容量 + 原容量/2（即原容量的1.5倍）；
  • 底层操作：扩容时创建新的数组，将原数组的元素复制到新数组，再将新数组赋值给底层数组，扩容是耗时操作，实际开发中若已知元素个数，建议指定初始容量（new ArrayList<>(initialCapacity)），减少扩容次数。
  1. 集合判空的正确方式
    实际开发中需区分集合对象为null和集合为空（元素个数为0），正确判空代码：

    // 集合不为null且有元素，执行操作
}

  1. 遍历方式的选择

    遍历方式 优点 缺点 适用场景
    基础for循环 支持索引操作，可修改元素 写法稍繁琐 需要操作索引（如删除/修改指定索引元素）
    增强for循环 写法简洁，无索引 无法操作索引，不能删除元素 仅需遍历元素，无需索引操作
    forEach流式遍历 最简洁，支持Lambda表达式 无法操作索引 JDK8+，简单遍历/批量处理元素

  2. ArrayList的线程安全性
    ArrayList是非线程安全的集合，多线程环境下同时操作集合会导致数据错乱（如ConcurrentModificationException）；

  • 线程安全替代方案：Vector（古老实现，效率低）、Collections.synchronizedList(new ArrayList<>())（包装成线程安全集合）、CopyOnWriteArrayList（JUC包，高效线程安全，适合读多写少场景）。

    使用增强for/forEach遍历时，直接调用remove()方法会抛出ConcurrentModificationException（并发修改异常），原因是遍历器的修改次数与集合的实际修改次数不一致；

  2. 基础for循环（从后往前删，避免索引偏移）；

包装类（Wrapper Class）

  • 定义与作用

Java 中 8 种基本数据类型不具备对象的特性（无属性、无方法），而集合只能存储引用数据类型（对象），因此需要包装类将基本数据类型封装为对象，实现基本数据类型与对象的相互转换。

  • 8 种基本数据类型对应的包装类
基本数据类型 包装类 特殊说明
byte Byte 首字母大写
short Short 首字母大写
int Integer 特殊，非 Int
long Long 首字母大写
float Float 首字母大写
double Double 首字母大写
char Character 特殊，非 Char
boolean Boolean 首字母大写

  • 内存角度理解包装类

    • 基本数据类型：变量直接存储数值，存于栈内存；

    • 包装类：是 Java 预定义的类，对象存于堆内存，栈中仅存储对象的内存地址，本质是把基本数据类型用对象包起来。

  • 自动装箱与自动拆箱（JDK5 + 核心特性）

    • 自动装箱：基本数据类型自动转换为对应的包装类对象（如list.add(10) → 自动转为Integer.valueOf(10)）；

    • 自动拆箱：包装类对象自动转换为对应的基本数据类型（如Integer num = 20; int n = num;）；

    • 作用：简化包装类与基本数据类型的转换代码，无需手动创建包装类对象。
